# 05 内容规范

版本：1.0.0 ｜ 日期：2026-08-02 ｜ 范围：DS 组件内建文案与消费方在 DS 组件里填入的内容

## 1. 术语表（起步集）

只收 DS 自身概念的对外叫法；业务术语（订阅、套餐、租户……）明确不收，归各产品。

| 英文       | 中文           | 判据                                                                                          |
| ---------- | -------------- | --------------------------------------------------------------------------------------------- |
| component  | 组件           |                                                                                               |
| variant    | 变体           | 意图与状态轴（primary/destructive…）                                                          |
| size       | 尺寸           | 上下文尺寸轴（sm/default/lg）                                                                 |
| density    | 密度           | 用户偏好轴（紧凑/默认/宽松三档）                                                              |
| font scale | 字号档         | 用户偏好轴（小/默认/大三档）                                                                  |
| tone       | 语气           | 六档严重度：中性 neutral / 品牌 brand / 提示 info / 成功 success / 警告 warning / 危险 danger |
| pattern    | 模式（图案件） | 上游没有的组合件                                                                              |
| template   | 模板           | 页面级骨架                                                                                    |
| token      | 设计 token     | 不译作"令牌"                                                                                  |

语气只表达严重度，不表达业务状态：把"订阅逾期"映射成 warning 是产品的判断，不进 DS。

## 2. 文案语气

| 判据                           | 说明                                                                 |
| ------------------------------ | -------------------------------------------------------------------- |
| 清爽、不喊话                   | 陈述句，不用感叹号，不堆修饰词；按钮用动词（"保存"，不是"点击保存"） |
| 错误文案 = 发生了什么 + 怎么办 | 面向用户的行动，不暴露技术细节（不出现状态码、异常名、堆栈）         |

## 3. 格式

| 项       | 规则                                                                                   | 示例         |
| -------- | -------------------------------------------------------------------------------------- | ------------ |
| 日期时间 | `Intl.DateTimeFormat("zh-CN")`（DatePicker 现行为，`dateStyle: "long"`），不手拼格式串 | 2026年8月2日 |
| 数字     | 千分位分组（`Intl.NumberFormat`）                                                      | 12,345       |
| 单位     | 数值与西文单位间留一个空格；与汉字单位不留                                             | 128 GB；3 天 |
| 截断     | 省略号截断用 CSS（`truncate`），不在数据层截字符串                                     |              |
| 空值     | 统一显示 "—"（em dash），不留白、不写 "null"/"暂无"                                    | —            |

## 3.1 件内文案：英文托底，应用必须传参

两条约定，缺一不可：

1. **每一处渲染文案都有覆盖出口。** 这一条使 DS 完全兼容 i18n——不是「支持某几种
   语言」，是任何一处文字都换得掉，包括只给读屏听的 `aria-label` 与 `sr-only`。
2. **默认值一律英文，且它只是托底。** DS 不知道消费方说什么语言；件内写中文就等于
   替某一个产品做了语言选择，而那个选择对别的产品是错的。英文是这里唯一中立的
   那一个。

**所有应用都应当传参**，中文单语的产品也不例外。默认值不是「中文产品不用管」的
豁免——它是兜底：**英文默认值出现在生产界面上，说明有人忘了传，不是一种受支持的
配置**。托底的意义在于漏传时界面仍然可读、不出现空字符串或 `undefined`，而不是
让人依赖它。

出口按文案条数分三档：

| 文案条数       | 收法                        | 先例                                                                  |
| -------------- | --------------------------- | --------------------------------------------------------------------- |
| 一两条         | 独立 prop                   | `DialogForm.cancelLabel`、`Banner.dismissLabel`                       |
| 三条以上       | `labels` 对象，与默认值合并 | `DataTable.labels`、`ShellSearchBox.labels`                           |
| 拼接出来的句子 | **模板**，不是词            | `ConfirmDestructive.titleTemplate`、`BulkActionBar.selectionTemplate` |

第三行是最容易漏的一条：**语序是语法，不是词汇**。`BulkActionBar` 曾只开 `noun`
一个口子而把「已选择 {count} {noun}」写死——中文是那个语序，英文得是
`{count} {noun} selected`，只给一个词换不出那句话。件替调用方拼串，就等于替它
定了语序。这一档是 i18n 兼容性的真正门槛：只收词的件，看着有出口，实际换不了语言。

应用侧建议把 labels 收在一份共享常量里，而不是逐个调用点手写——否则同一个
「取消」会在不同页面上长出不同的写法，那正是 DS 收口这些文案要解决的问题。

第 2 条由 `scripts/guardrails/check-i18n-seam.mjs` 机器判定，进 `pnpm guardrails`：
剥掉注释后，组件源码里不允许出现中日韩字符或全角标点。判据是二值的，没有启发式，
也就不存在「看起来在查其实没查」的中间态。**注释不受此限**——注释是写给维护者的，
本仓的维护语言仍是中文。

第 1 条与第 3 档「够不够」机器查不了，靠评审与上面这张表。

## 4. 句式模板

| 场景         | 模板                                                                                                                                                                                                 |
| ------------ | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 空态         | "还没有{对象}"＋可选一步动作（"创建{对象}"）；"没有匹配的{对象}"（筛选后为空，附"清除筛选"）                                                                                                         |
| 错误         | "{动作}失败：{原因}。{建议动作}"；原因不可知时："出了点问题，请稍后重试"                                                                                                                             |
| 确认（危险） | 标题"{动词}{对象}？"＋后果一句（"删除后不可恢复"）＋按钮用动词本身（"删除"，不是"确定"）。**这一行自 design-ui 4.0 起由 `ConfirmDestructive` 的 `verb` / `target` / `consequence` 强制**，不再靠人记 |
