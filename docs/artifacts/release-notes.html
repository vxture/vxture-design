发版说明

升到 design-system 10.0.0 要做什么、不用做什么。这一版是 major：三个包同时升，且必须一起升。要改的只有一类——写着 -none 的间距工具类。§02 是清单，§03 是那些不用改但行为变了的。

01现在该装什么2026-08-28 · major

应用只装伞包。直接装 design-ui 拿不到运行时接线（主题 / 密度 / 字号 provider），且版本约束不再由伞包保证。

包版本这次动了吗
@vxture/design-system10.0.0major 应用侧主依赖，装这个
@vxture/design-ui7.0.0major 由伞包精确钉版，不要直接装
@vxture/design-tokens3.0.0major 删了一个 token 档——见 §02
三个包必须一起升。伞包对另两包钉的是精确版本，装 10.0.0 就会带上 ui 7.0.0 与 tokens 3.0.0；不要单独升其中一个。

为什么 tokens 也是 major：删掉一个 CSS 变量不会报错，只会静默失效——没有编译器会告诉你 var(--space-none) 现在解析不到。所以 token 的删改一律按 major，不做「应该没人用」的推定。

⚠ registry 上没有 6.0.5 与 6.0.6：这两批合并后未单独打标签，随 6.0.7 一并发出。CHANGELOG 里各自留有条目。

02必须改的10.0.0 major

--space-none 不再注册进 @theme，凡是写 p-none / gap-none / pt-none 这类的地方，类名从此不产出任何规则。不报错，只是那处内边距静默变回浏览器默认。

none 是 CSS 全局关键字，在不同属性上含义不同：padding 上我们想表达 0，而 max-width: none 是「无上限」、line-height 的 Tailwind 原义是 1。把字面词 none 登记进 spacing 命名空间之后，凡是读 spacing 档的工具类族都会把 X-none 解析成 0——Tailwind 不区分「这个族的 none 是不是 0」。

实测一个门户的编译产物，14 个 *-none 落到这一档，12 个对、2 个错：

.leading-none { line-height: var(--space-none) }   → 0，应为 1
.max-w-none   { max-width: none;
                max-width: var(--space-none) }     → 0，应为 none
max-w-none 尤其隐蔽。Tailwind 先输出自己的 max-width: none，再被本档覆盖——类名照常生成。「这个类有没有产出」这一类检查全是绿的，只有比对取值才看得见。实际后果：三个门户 18 处 DialogTitle 行高归零、标题与描述叠字，以及对话框写 max-w-none 被夹成 34px 宽。
这条修复的回归断言，覆盖面有个限度，说明白。DS 仓里为它写了两条断言，但只有 leading-none 那条能在本仓自己的编译上跑出来；max-w-none 的双声明只在 Next / Turbopack 里复现——同一段 CSS，不同构建器的产出形态不同。

两者是同一个成因（字面词 none 进了 spacing 命名空间），抓住任一即抓住成因，所以没有为此再搭一套 Next 构建。但这不等于两条都被覆盖了，限度写在了 DS 的代码注释里，这里一并告诉你：如果哪天你的门户换了构建器，max-w-none 这一侧没有回归网接着——那时值得手动比对一次编译产物的取值，而不是只看类名有没有产出。
你写的改成为什么
p-none · px-none · pt-none …p-0 · px-0 · pt-0 …Tailwind 内建档，含义完全相同
gap-none · space-x-nonegap-0 · space-x-0同上
inset-x-none · top-none …inset-x-0 · top-0 …同上
leading-none · max-w-none不用改它们本来就该是 Tailwind 原义，现在才终于是
怎么找：
grep -rnE "(p|px|py|pt|pr|pb|pl|m|mx|my|gap|gap-x|gap-y|space-x|space-y|top|right|bottom|left|inset|inset-x|inset-y)-none" src/

不要连 leading-none / max-w-none 一起改——那两个是这次修复的受益方，不是迁移对象。
为什么不补一个 --leading-none 了事。那不是设计令牌，是为了在名字解析上抢赢 spacing 档而造的影子值——一个叫「none」的行高不表达任何设计决策。而且它只管一族：max-w-none 要再造 --container-none，min-w-none、max-h-none 各自还要一个，每个「CSS 里 none ≠ 0」的属性族都得再补一次。根因只有一个：none 不该是间距档的键名。

03还没迁完 9.0.0 的看这里上一次 major

variant="destructive" 的 Button / ActionButton 现在会编译失败，除非写明为什么不设防。这是「红」与「拦」变成同一个决定的最后一块。

此前判别联合只管 ActionMenuItem 与 BulkActionBarItem，够不到裸的红按钮——于是 grep confirmExempt 会把只有裸红按钮的产品报成「干净」。清单不完整就不能当清单用。

要拦换成 DestructiveButton
<DestructiveButton
  confirm={{
    verb: "Revoke",
    target: passkey.name,
    consequence: "…",
    preconditions: [
      { label: "至少还有一把可用的 passkey",
        met: others.length > 0 },
    ],
    onConfirm: () => revoke(passkey.id),
  }}
>
  Revoke
</DestructiveButton>
不拦写明理由，理由可 grep
<Button
  variant="destructive"
  confirmExempt="确认在流程第二步"
>
  …
</Button>

confirmExempt 收字符串而不是布尔，是为了让「本产品有多少个不设防的红色动作」变成一条 grep。它从不进 DOM。

destructive-strong
不要求。它是落锤档——确认对话框里的那个提交按钮。要求落锤自己再确认一次是循环
DestructiveButton 的限制
不开 variant（按定义就是 destructive 入口档），也不开 asChild（它渲染「按钮 + 对话框」两个节点，塞不进 Slot 的单子元素约束）。AlertDialogTrigger asChild 这类场合用 Button + confirmExempt
variant 是运行时值时
遍历全部挡位的画廊选不出分支，需要回收一次类型——预览面的 galleryVariant 是这个写法的样板

04不用改，但行为变了八个 patch

下面八条不需要你动任何代码，但它们改的是「本来就该这样、此前一直不是」的行为。如果你为这些症状做过绕法，绕法现在可以撤了。

版本症状（你可能见过的样子）绕法可以撤吗
6.0.8Progress 的取值从来没传给过读屏器。色条画在 70% 的位置，但 aria-valuenow 一次都没发出去、data-state 永远停在 indeterminate——听到的是「正在忙」，不是「已完成 70%」。同版还修了 max 不为 100 时填充位置与取值对不上注意 如果你用 [data-state="indeterminate"] 选中「有取值的进度条」，那个判据现在失效了——有取值的会是 loading / complete
6.0.7InputOTPSlot 脱离 <InputOTP> 单独渲染时直接抛 TypeError。件里那个 ?. 从来没生效过——上游 context 的默认值是个真值空对象，短路条件永远不成立可以 如果你为此包过 try/catch 或避开了单独渲染
6.0.6FullscreenProvider：从锁滚动的面板切到不锁的面板，退出后整页滚不动。刷新就好，下次照样注意 如果你为此在退出后手动重置过 document.body.style.overflow，现在可以撤——但要确认没有别的地方依赖那次重置
6.0.5Toast 同一毫秒连发两条时，两条可能共用一个 React key，后一条把前一条顶掉。只在手快时偶发可以 如果你为此自己传过 id——不过自己传 id 一直是合法用法，留着也没问题
6.0.4原生全屏退出时控制台一条 TypeError——exitFullscreen() 被调了两次，第二次时文档已不在全屏态可以 如果你 catch 过它
6.0.3EntryCard 只给 onClick 不给 href 时，鼠标点得到、键盘进不去。而且两者都不给时，卡也一直摆着可点的外观可以 如果你手动补过 role / tabIndex
6.0.2MetricListCard 上焦点停在「更多」按 Enter，菜单不开、详情打开了。鼠标那条路一直是对的，所以这个洞只在键盘上存在可以 如果你在行操作上加过 stopPropagation
6.0.1Drawer 的 width="sm" | "md" | "lg" 一直是死的，一律渲染成 w-full max-w-panel-lg。没有任何报错，DOM 上连那条类都不剩注意 如果你用 className 或内联样式盖过宽度，现在挡位真的生效了，两者会打架
6.0.1 那条值得单独看一眼。挡位失效期间，任何需要窄抽屉的地方只能靠外部盖宽度。现在挡位活了——cn 把 --container-* 登记进了宽度组，你外部再传一个宽度类，谁赢取决于书写顺序，而不是你的意图。升级后请检查所有传了 width 又同时盖过宽度的 Drawer。
6.0.2 文档更正
AlertDialog 的 Esc 是关得掉的。头注此前写「Esc 与点遮罩也不关」，错了一半：Esc 触发 onOpenChange，外点不触发。Esc 能关是对的——没有键盘出路的模态是键盘陷阱。「要求表态」靠的是拿掉随手可点的出口（无 X 钮、外点不关），不是堵死所有出口

05怎么确认自己迁完了一条 grep

6.0 之前需要两条 grep，其中一条是纯人工纪律、没有任何强制力——正是这套契约一开始要消灭的东西。现在回到一条：

grep -rn confirmExempt portals/
这条 grep 现在是完整的

因为剩下的情况编译不过：要拦的走 DestructiveButton，不拦的必须写 confirmExempt。没有第三种写法能通过 tsc。ActionButton 透传 ButtonProps 自动跟着收紧——它的 Omit 换成了 DistributiveOmit，否则 TS 会把联合分支先并成一个「什么都可选」的对象再删键，variant 与 confirmExempt 的绑定当场丢失，ActionButton 就成了绕开契约的后门。

grep 出来之后读什么

读理由本身。confirmExempt 收的是散文不是布尔，就是为了让这份清单可以被人评审：「确认在流程第二步」是个理由，"ok" 不是。清单比错误有用——但前提是清单完整，不完整的清单比没有清单更坏。

06报错查到 DS 头上时先做对照组

这一节是 2026-08-26 一次真实误判的产物，写在这里是因为它会再发生。

消费端报来一条 React key 警告，追进 DS 的构建产物，看到 Section 用的是 jsx 而不是 jsxs，结论是「根因在 DS，改一个字符就行」，并登记了技术债等 DS 修。结论是错的，而链条讲得通——这正是它值得记下来的原因。
对照组结果
<Section>{a}{b}{c}</Section> 静态多孩子不报警
中间层拼数组 → 交给 Section报警
中间层拼数组 → 交给裸 <div>（DS 完全不参与）同样报警
中间层改用带 key 的 Fragment → 交给 Section不报警

裸 <div> 报的是同一条，所以跟 DS 无关。第一行同样关键：Section 内部对 children 用 jsx 并不引发警告——静态多孩子在外层 jsxs(Section, …) 那一步就被标记成已校验了。这也是为什么 React 生态里成千上万个包 children 的组件不会集体刷屏。

为什么会查到 DS 头上

React 的警告原文点了两个名字，恰好都不是真凶：

Check the render method of `Section`.
  ← 收下这个数组的件（DS 的）

It was passed a child from AccountDetailPage.
  ← 元素被创建的地方（你的页面）

真正拼出无 key 数组的中间层一个字都没被提到。顺着两个名字走，一个通向 DS，一个通向页面，中间层正好被跳过。

这条警告不该被压掉

它指向的是真会咬人的东西。[a, b].filter(Boolean) 少一个成员时，后面的会落到前面的索引上，React 按索引复用实例——同类型的兄弟之间状态会串：

[改动前]   A:0  B:3   ← 把 B 的计数器点到 3
[A 消失后] B:0        ← B 落到索引 0，捡了 A 那一格

DS 不会用 Children.toArray 之类的手法把它吃掉：那等于把你的真缺陷盖住。DS 保证的是自己不出这个形状——测试基座现在把 key 警告一律判失败，189 条用例零警告。

规矩：怀疑 DS 是根因时，先造一个不含 DS 的对照组。症状在对照组里照样出现，讨论就结束了；照样不出现，才轮到看 DS 的实现。这比读三层调用链快，也比读构建产物可靠——产物里的 jsx / jsxs 是编译器按调用点决定的，不是作者的选择。
