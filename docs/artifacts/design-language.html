Vxture Design System · vxture-design

设计语言

token 两层、语气六档、危险两档、三根互不相干的轴。每一条刻度都有载体——写进文档而没有载体的判据，只对读过那一页的人生效。

01为什么是两层T1 取值 · T2 语义

一层不够，是因为「这是什么颜色」和「这块该用什么颜色」是两个问题。把它们写在一起，换主题就得改所有调用点；分开之后，换主题只改 T2 的一层映射。

T1 · 原子层21 文件 · 247 个变量

镜像 Tailwind 的刻度：颜色、间距、圆角、阴影、模糊、缓动、断点、容器、字体族与字重。这一层没有意见——它只回答「有哪些取值可选」。

件不许直接用 T1。用了就等于把「这块是 slate-700」写死，换品牌时无处可改。

T2 · 语义层11 文件 · 756 个变量

产品面：--color-primary、--spacing-md、--text-body-md-font-size。这一层全是意见——它回答「主色是哪一个 T1 取值」。

件只认 T2。品牌、明暗、密度、字号四种切换，全部发生在这一层的重定义里，件一个字都不用改。

两层全部由脚本生成并入仓，CI 里没有任何步骤会重新生成它们。入仓不是偷懒——生成物入仓，diff 才看得见「这次改了哪 3 个取值」。11 个 token 脚本的 --check 模式只负责守「入仓的这份与策略源同步」，不负责生成。
token 的删改一律按 major，不做「应该没人用」的推定。判据与代码层不同，是因为载体不同：删掉一个 CSS 变量不会报错，只会静默失效——没有编译期能接住它。

02色彩明暗两套，各 132 个

键集必须相等
:root
132 个语义色
:root.dark
132 个，同一套键

暗色块少一个键，那个件在暗色下会继承亮色的值——不报错，只是难看，而且只在切到暗色时才看得见。check-mode-blocks 守的就是这个：键集、块顺序、特异性三样一起验。

用实色阶，不用 alpha

危险按钮的淡底用 --destructive-muted 这样的实色阶，而不是上游那种 destructive/10。

两个理由：alpha 叠在未知底色上结果不定（卡里、抽屉里、表格行上各是一个色）；alpha 不自适应暗色——上游为此要补写一行 dark:，而实色阶在 T2 里已经分好了明暗两套。

03排版21 个角色 × 5 个属性 × 3 档字号

角色不是字号——是「这段文字在信息层级里是什么」。选 body-md 是在说「这是正文」，不是在说「这是 16px」。

族档位用在哪
displaylg · md · sm营销面、空态里的大字
heading1 · 2 · 3文档流的标题层级
titlexl · lg · md · sm件自己的标题：卡头、板块头、对话框头
bodyxl · lg · md · sm正文
labelxl · lg · md · sm控件上的字：按钮、字段名、标
codemd · sm等宽
overline——小字眉标，通常大写加字距
每个角色带 5 个属性
--text-body-md-font-family
--text-body-md-font-size
--text-body-md-font-weight
--text-body-md-line-height
--text-body-md-letter-spacing

行高与字距跟着角色走，不是各处现调。21 × 5 = 105 个变量，三档字号各定义一遍 = 315，加两个全局项共 317。

中文的行高补偿
:root      { --vx-cjk-leading-add: 0 }
:lang(zh)  { --vx-cjk-leading-add: 0.15 }

汉字的字面框比拉丁字母满，同样的 line-height 看上去更挤。这条补偿挂在 :lang(zh) 上而不是写死——同一份组件要同时排中英文，写死就总有一边不对。

三档字号不是「各自重设 105 个值」，是让每个角色在 T1 刻度上整体挪一档。以 body-md 为例： 
html.vx-font-small    --body-md-font-size: var(--vx-text-xs)
:root / vx-font-default  --body-md-font-size: var(--vx-text-sm)
html.vx-font-large    --body-md-font-size: var(--vx-text-base)

整套角色一起挪，层级关系因此在三档里保持不变——标题仍然比正文大一档，而不是三档各自调出三套不同的层级观感。行高跟着同一步走。

04间距与密度29 个 × 3 档

密度不是缩放——是同一套语义间距的三组取值。件写的永远是 gap-md，换密度时 --spacing-md 变，件不动。

:root, .density-default   { --spacing-* : … }   29 个
.density-compact          { --spacing-* : … }   29 个
.density-comfortable      { --spacing-* : … }   29 个
为什么不用 transform: scale 或根字号缩放：那会把边框、圆角、阴影、图标一起缩，结果是「同一个界面被拉远了」，而不是「同一个界面更紧凑」。紧凑是把留白收掉，不是把东西变小——字号是另一根轴，谁要小字自己调那根。
层叠阶梯12 档，留了空隙
base          0      drawer      400
raised       10      modal       500
sticky      100      popover     600
overlay     300      dropdown    650
toast       700      notification 800
tooltip     900      max        9999

档与档之间留空隙，是为了让产品能在两档之间插一层而不用改 DS。dropdown 排在 popover 之上是实测定的：菜单从浮层里开出来的场合比反过来常见得多。

05语气六档只表达严重度

neutral   brand   info   success   warning   danger
这里没有 overdue / suspended 之类的值，而且不会有。把「订阅逾期」映射成 warning 是产品的判断——不同产品对同一状态的严重度本就可以不同。DS 一旦收下这个映射，就等于把业务语义焊了进来。
单独成文件是有原因的

StatusBadge 与 Banner 说的是同一件事。各写各的档位，同一个语气在两处迟早会有两个名字。新的件要表达语气，一律引 tone.ts。

运行时数组而不是只有类型
export const TONES = [...] as const;
export type Tone = (typeof TONES)[number];

预览面与图案件要遍历全部档位时引这个数组，不再各自手抄一份——手抄的清单加了档位不会跟着加，而且不报错。下游三个 Record<Tone, …> 以此为键，档位漂移在编译期就报。

06危险两档判据是数量

档长什么样用在哪要不要确认
destructive淡底 + 同色前景入口按钮：列表行上的删除、菜单里的撤销要（或写豁免理由）
destructive-strong实心红落锤：确认对话框里的那个提交不要——要求落锤自己再确认是循环
为什么入口不用实心红

判据是数量。入口按钮一屏可能有十个，实心红会把视觉重量全吸过去——一屏十个红块，等于没有红块。而确认按钮一屏只有一个，且按下去不可撤销，弱化它是在帮倒忙。

真正的拦截交给二次确认，不靠按钮颜色吓人。

「红」与「拦」是同一个决定

这是 6.0 契约的全部内容：variant="destructive" 必须要么带确认，要么写明为什么不设防，判别联合在编译期拦住第三种写法。

豁免收字符串不收布尔，是为了让「本产品有多少个不设防的红色动作」变成一条可评审的清单——详见接口文档 §06。

07三根轴互不相干，这是设计

轴档位载体它不管什么
明暗light · dark · 跟随系统:root.dark不管字多大、不管多紧凑
密度compact · default · comfortable.density-*不管字号——紧凑不等于小字
字号small · default · largehtml.vx-font-*不管间距——大字不等于宽松

三轴正交，所以是 3 × 3 × 2 = 18 种组合，而不是三档「大中小」。把它们并成一根轴会逼用户在「字大但太挤」和「字小但太空」之间二选一，而这两个诉求本来就来自不同的人：字号是视力，密度是信息量偏好。

主题要在 React 之前定

themeBootstrapScript 在 /server 与 /tokens 两个入口里都有——它必须在首帧之前把属性打到 <html> 上。晚一帧就是一次白闪，而白闪在暗色用户那里格外刺眼。

三档不是三倍工作量

件一次都不用为档位写分支——它们写的是 gap-md 与 text-body-md，三档在 T2 里已经各定义了一遍。档位漂移只可能发生在 token 层，而那里有 check-mode-blocks 守着键集一致。

这一页描述的每一条刻度都有载体。颜色与间距在 token 的模式块里（check-mode-blocks 守键集）；语气六档在 TONES 数组里（档位漂移编译期报）；危险两档在判别联合里（写错编译不过）。写进文档而没有载体的判据，只对读过那一页的人生效——这是这套系统四个 major 反复在回答的同一个问题。
