## SonarCloud

### `sort()` 缺比较函数 · 5 处 · CRITICAL

|          |                                                                                                          |
| -------- | -------------------------------------------------------------------------------------------------------- |
| 位置     | `generate-reexports.mjs:35`、`check-design-system-exports.mjs:63/81/121`、`check-design-system.mjs:2798` |
| 工具主张 | 提供比较函数，最好是基于 `String.localeCompare`                                                          |
| 结论     | **误报**，不改                                                                                           |

**原理。** `Array.prototype.sort()` 不带比较函数是把元素转成字符串、按 **UTF-16 码元**
比较——跨机器、跨 locale 完全确定。而 `localeCompare` **按 locale 变**（瑞典语里
`å` 排在 `z` 之后）。

**照它改会发生什么。** 这几处排的是生成物里的导出名与键名，生成物入仓、由
`--check` 逐字节对账。换成 `localeCompare` 之后，同一份源码在不同 locale 的机器上
会生成**不同顺序**的文件，`--check` 于是在别人的机器上假红。

**也就是说工具警告的那个后果，恰恰由照它改造成。**

> 第一轮审计报告初版写的是「排序不稳会让对账在别人机器上假红，sort 那几处值得
> 先看」——因果写反了。报告已勘误。

**复核期限**：2027-02，或本仓开始用 `sort()` 排**给人看的**列表时（那时 locale
敏感排序才是对的）。

### 非交互元素挂点击处理 · `MetricListCard.tsx:151` · MINOR

|          |                                                      |
| -------- | ---------------------------------------------------- |
| 工具主张 | 可见的非交互元素挂了 `onClick`，至少要有一个键盘监听 |
| 结论     | **误报**，不改                                       |

那个 `<div onClick={(e) => e.stopPropagation()}>` **不是交互元素**，它唯一的作用是
拦住冒泡——点"更多"是要开菜单，不是进详情。整卡的交互性在外层 `<article>` 上：
`interactive` 为真时它带 `tabIndex={0}`、`onClick`、`onKeyDown`。

键盘路径也是通的：焦点落在内层按钮上按 Enter 会**产生一个冒泡的 click 事件**，
同样被这个 `stopPropagation` 拦住。加一个 `onKeyDown` 不会改变任何行为，只会让
下一个读代码的人以为这里有键盘逻辑。

**复核期限**：`MetricListCard` 的交互结构改动时。

### `iconDictionary.ts` 重复率 92.9%

不是误报，是**不该去重**。图标字典是一张平表，14 个 `{ label, icons: [...] }`
结构相同内容不同；给一张数据表发明抽象只会更难读。已走
`sonar.cpd.exclusions`，**只关重复这一项**，该文件其余规则照查。

**复核期限**：字典改成分层结构时。

### `docs/artifacts/**` 的一切

|          |                                                             |
| -------- | ----------------------------------------------------------- |
| 工具主张 | 缺 `<!DOCTYPE>`、缺 `lang`、重复率 27.4%、若干 CSS/JS smell |
| 结论     | **整目录排除**，不改                                        |

三条理由：

1. **它们是页面片段**，由 Artifact 宿主包 doctype / html / head。按整页规则扫必然
   报缺 doctype——报的是一个不属于这份文件的东西。
2. **重复是这个格式的定义**。四份文档共用同一套版式与配色，正因为
   「一个每换产品就换配色的文档系统，是三个产品，不是一个系统」。去重就是拆散它。
3. `_reference-karda-audit.html` 是另一份已发布页面的**逐字节副本**，入仓只为给
   `check-doc-shape` 对账。**去「修」它就等于让参照物不再是参照物。**

**复核期限**：文档形制换代时。

### `execFileSync` 依赖 PATH · `self-test.mjs`

已按工具的意思改掉，不留在此列——但改法值得记：不是给 `git` 加绝对路径，而是
**整个不再调 git**。自测只碰固定那几个文件，逐个比对字节能指出是**哪一个**没还原，
比问全局 git 状态更精确；顺带去掉一个子进程，也去掉了「改到一半不许跑自测」那道
纯属自找的门槛。

**工具报了一个真信号，但最好的修法不是它建议的那个。**
